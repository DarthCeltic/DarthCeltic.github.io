How to create a run on your own machine

Start with a target you have permission to use. Review the exact statement and spending limits first. Keep credentials in your local environment and run candidate code only in the pinned Lean sandbox.

The MathCase command requires an owner grant, input clearance, a specific provider and model, approved prices, and a hard spending cap. This version accepts HTTPS provider endpoints only. Local HTTP Ollama endpoints are unsupported.

Replace the placeholders before running this template in Bash. In PowerShell, put the arguments on one line and omit the backslashes.

mathcase solve-provider --dispatch \
  --problem <cleared-problem.json> \
  --owner-authorization <owner-grant.json> \
  --input-clearance <item-clearance.json> \
  --provider <approved-provider> --protocol <protocol-id> --model <exact-model-id> \
  --base-url <approved-endpoint> --api-key-env <ENVIRONMENT_VARIABLE_NAME> \
  --input-price-micros-per-million <reviewed-rate> \
  --output-price-micros-per-million <reviewed-rate> \
  --per-call-ceiling-micros <cap> --run-ceiling-micros <cap> \
  --max-provider-calls 1 \
  --run-id <unique-run-id> --output <new-result.json> \
  --cost-journal <local-cost-ledger.jsonl> --provider-evidence-dir <local-call-evidence> \
  --lean-snapshot-manifest <pinned-snapshot.json> \
  --lean-sandbox-image sha256:<approved-image-digest> --lean-receipt-root <local-receipts>

Do not paste API keys, owner grants, clearance files, local paths, or raw request/response files into a public page. A visitor controls provider dispatch and spend.

A run summary reports what happened. To confirm that Lean accepted a proof, check the pinned Lean receipt against the exact source and statement.
