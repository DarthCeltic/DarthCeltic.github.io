VP versus VNP: a two-by-two example

In a 2×2 grid of ones, two choices take one entry from each row and column. The permanent adds them to 2; the determinant subtracts one to give 0. This example does not prove the upstream result.

MathCase checked the example, rejected a deliberately wrong answer, and matched seven source files at the pinned upstream commit. It did not compile the upstream Lean proof or validate the theorem independently. The result concerns arithmetic circuits, not ordinary P versus NP. Credit for the result and formalization belongs to Anthropic's formal-math project.

Run the checked example from a MathCase clone: python scripts/run_public_case.py vp-vnp-example. The separate source audit is python scripts/run_public_case.py vp-vnp-source-audit.

Matrix multiplication exponent 9/4

For A = [[1, 2], [3, 4]] and B = [[5, 6], [7, 8]], the ordinary and Strassen formulas both give [[19, 22], [43, 50]]. The ordinary calculation uses eight multiplications and four additions; Strassen's uses seven multiplications and 18 additions or subtractions.

The local checker covers this one exact example and a deliberately damaged sign. A local Lean build timed out in a prerequisite before reaching the pinned theorem or an axiom audit. The separate Comparator workflow was not run. The exponent claim belongs to the upstream authors.

Riemann hypothesis source check

The statement is that every nontrivial zero of the Riemann zeta function has real part ½. Levent Alpöge published the Claude-assisted proof; the Lean FRO and Mathlib Initiative coordinated independent checks. The proof and result belong to those upstream authors and community.

MathCase checks byte counts and SHA-256 values for four pinned public source files. It does not download the proof export, elaborate the theorem, replay the proof, or independently validate the result.

    Arithmetic diagnostic · not a new theorem

    A shorter way to check the 23/14 arithmetic

    For the existing 23/14 bounded-drop rule, the endpoint gets larger as the number of odd shortcut moves increases. That means the large-number arithmetic can use one endpoint inequality instead of fifteen separate cases. A separate finite check covers the starts below 677.

    MathCase checked the identity and endpoint constants in Python, then checked all 674 starts from 3 through 676 twice: 548 met the stated parity filter and all 548 dropped. This is a proof-organization aid, not a new Collatz result, convergence proof, or Lean replay.

    Saved Lean attempt · wording review and independent replay open

    860 selected Collatz progression families

    Older files use “M31 v1” as this package’s archive label; it is not a standard mathematical term. The saved Lean record reports a bounded first-drop result for 860 selected groups of Collatz starting numbers. Each group contains infinitely many starts: take a fixed offset and add the same fixed jump size any whole number of times. The recorded form is r + 2dk, with k = 0, 1, 2, …. The public Python route checks saved file bindings and arithmetic; it does not run Lean.

    The source-selection process has not been independently reproduced, the exact statement has not received a recorded M0 review, and a fresh anonymous Lean replay remains open. This does not prove Collatz convergence or cover every start.

    Lean checked · bounded coordinate model

    Geometry: the midpoint of a right triangle

    Question: if a right triangle has corners (0,0), (a,0), and (0,b), is the midpoint of the longest side equally far from all three corners? The small coordinate calculation says yes.

    A fresh replay of the exact pinned source compiled and passed its axiom audit. The result is for this normalized coordinate model only; it does not formalize the conversion from every abstract Euclidean triangle into coordinates.

    The audit reported [propext, Classical.choice, Quot.sound] and no sorryAx. Earlier setup failures remain preserved in the package history.

    Run from a MathCase clone: python scripts/run_public_case.py geometry-midpoint --stage-timeout 600. This checks the source, pinned lock, build, and audit with a ten-minute stage cap.
